Week 3 — Beneath the Webpage: From HTML to Web Scraping

Digital Practice | Weekly Reflection

Looking at Websites Differently

After spending the previous week learning how to build a website using HTML and CSS, this workshop introduced me to a rather different way of interacting with webpages: web scraping.

Instead of creating and organising content, I was now trying to extract information from a website that someone else had built.

We experimented with the Web Scraper browser extension, using BBC iPlayer as an example. The aim was to identify individual programmes and extract their titles into a structured dataset.

At first, this sounded relatively simple. The programme titles were already visible on the webpage, after all. Surely collecting them would not be particularly difficult?

As it turned out, I was being a little optimistic.

When a Single Letter Matters

One of the first challenges was understanding how CSS selectors could be used to identify specific elements within a webpage.

Using Chrome's Developer Tools, I could inspect the HTML structure behind BBC iPlayer's programme cards. However, identifying the correct elements was not as straightforward as I had expected.

For example, I initially struggled with a selector intended to identify multiple programme cards. The difference between carousel and carrousel turned out to be surprisingly important.

One spelling returned no matching elements, while the other successfully identified the programme cards.

Apparently, in web scraping, a single letter can make the difference between collecting data and collecting absolutely nothing.

I also encountered another problem when my data preview displayed duplicate programme titles and several unnecessary columns labelled data, data2, and so on.

After checking the selectors and their parent-child relationships, I realised that I had created additional selectors that were not needed for the task.

Once I removed the unnecessary selectors, the preview finally displayed a single column containing programme titles.

A surprisingly satisfying result, considering how much time I had spent trying to produce something that looked so simple.

The Structure Behind the Content

This experience helped me understand the relationship between HTML and web scraping more clearly.

When browsing BBC iPlayer, I see programme images, titles, and neatly arranged categories. However, these visual elements are supported by a much more complicated HTML structure.

Web scraping requires me to look beyond the visual interface and understand how information is organised within that structure.

I also began to understand why parent selectors matter. By identifying each programme card first, I could then extract the title associated with that particular programme.

In this sense, web scraping is not simply about copying information. It involves recognising patterns and relationships within the underlying webpage.

This was an interesting continuation of my experience in Week 2. Previously, I had been learning how to construct a webpage. Now, I was learning how to take one apart.

Beyond the Technical Exercise

As someone with a background in journalism and content operations, I can see how web scraping could be useful for collecting and organising information.

Rather than manually copying individual pieces of information, scraping tools can help transform webpage content into datasets that are easier to examine and compare.

However, this workshop also made me aware of the limitations of automated data collection.

A scraper depends on the structure of the website it is examining. If that structure changes, a previously successful selector may stop working.

Furthermore, successfully extracting information does not automatically mean that the resulting dataset is complete, accurate, or appropriate to use.

There are also ethical questions worth considering, particularly when scraping information about individuals or collecting data from platforms with restrictions on automated access.

The technical ability to collect information is not necessarily the same as having permission to use it in any way we choose.

Final Thoughts

Before this workshop, I mainly understood websites as spaces where information is presented and consumed.

Learning about web scraping encouraged me to see them as structured sources of data as well.

Although I only experimented with extracting programme titles from BBC iPlayer, the process helped me connect my previous experience with HTML to a new digital research method.

More importantly, I realised that understanding digital tools involves more than knowing which buttons to click. It also requires understanding how those tools interpret, organise, and sometimes misinterpret information.

I am still very much a beginner when it comes to web scraping. But at least I now know why an extra letter, an incorrect selector, or an unexpected data column can cause so much trouble.

Small victories, I suppose.
