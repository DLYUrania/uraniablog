Week 2 — Behind the Interface: From Using HTML to Building a Website

Digital Practice | Weekly Reflection

Familiar, but Not Quite

HTML was not entirely unfamiliar to me before this workshop.

During a previous internship in content operations at a multinational company, I occasionally worked with HTML as part of my daily responsibilities. However, the webpages I worked on had already been developed by my colleagues in the programming team. My task was mainly to prepare and update content, then insert the revised text and code into an existing structure.

In other words, I knew how to work with HTML, but I had never built a website from scratch.

This distinction became much more apparent when I started creating my own digital portfolio.

From Existing Structures to a Blank Page

This week, we were introduced to different approaches to creating a digital portfolio, including CampusPress and GitHub Pages. I chose to experiment with HTML and CSS using Visual Studio Code, before publishing my website through GitHub Pages.

Unlike my previous experience, there was no pre-existing webpage waiting for me to fill it with content. I had to consider how the website should be structured, how different files interacted, and how its visual appearance could be controlled.

One of my first challenges was getting the CSS stylesheet to work properly. Although the HTML content appeared in the browser, the colours and formatting I had written did not display as expected.

After checking the files and experimenting with different solutions, I eventually managed to make the stylesheet work.

However, publishing the website introduced another small challenge: the changes I uploaded to GitHub did not appear immediately on the live page.

Apparently, creating a website also involves learning when to be patient.

Rethinking Digital Control

Looking back at my internship, I realised that working within an existing webpage had made many technical decisions almost invisible to me.

The layout, structure, and much of the functionality had already been determined by other people. I could update the content, but I had limited involvement in deciding how the system itself worked.

Building my own website made these previously hidden decisions much more visible.

It also encouraged me to think about the relationship between technical knowledge and creative control. Platforms such as CampusPress can make publishing more accessible by providing ready-made templates, but those templates also shape how users organise and present their content.

Working directly with HTML and CSS offers more flexibility, but it also introduces technical challenges that may discourage people without coding experience.

This made me realise that digital tools do not simply enable creativity. They also influence the choices available to their users.

Final Thoughts

My previous experience with HTML helped me feel less intimidated by the code, but this workshop revealed how different it is to use an existing digital system and to create one independently.

I began to understand web development not simply as writing code, but as making decisions about structure, presentation, accessibility, and user experience.

My portfolio is still a work in progress. However, I am beginning to appreciate the technical work that usually remains hidden behind the websites I encounter every day.

And I have developed a new level of respect for my former colleagues in the programming team.
